# API Usage Documentation

This document describes every endpoint in the WhatsApp Gateway.
**Base URL:** `http://localhost:3000/api/v1` (Default)

All responses are JSON. Successful responses use `status: "success"` or task-specific statuses. Errors use `status: "error"` with `message` and optionally `code`.

---

## 🔐 Authentication

The gateway supports three authentication methods.

### 1. User API Key (`x-api-key`)

For normal API consumers. Scoped to the sessions and templates they own.

- **Header:** `x-api-key: wak_xxxxxxxx.yyyyyyyy...`
- **Used by:** `/api/v1/sessions/*`, `/api/v1/templates/*`

### 2. Admin Bearer Token (`Authorization: Bearer`)

For programmatic server-to-server admin access (e.g., from another platform).

- **Header:** `Authorization: Bearer wak_adm_xxxxxxxx.yyyyyyyy...`
- **Used by:** any `/api/v1/*` endpoint (super-user, bypasses ownership)
- **Management:** created, revoked, and deleted via `/api/v1/admin/tokens` (or the built-in UI)

### 3. Admin Cookie (`admin_token`)

For the built-in frontend UI. Obtained by logging in with username/password.

- **How to get:** `POST /api/v1/admin/login` → sets `httpOnly` cookie
- **Used by:** any `/api/v1/*` endpoint (super-user, bypasses ownership)

> **Note:** The legacy `x-admin-key` header and `MASTER_API_KEY_HASH` have been removed for security reasons. Use Bearer tokens or cookie auth instead.

## 📏 Rate Limits

| Route Group                              | Window     | Max  |
| ---------------------------------------- | ---------- | ---- |
| `/api/v1/*` (sessions, templates, admin) | 15 minutes | 3000 |
| `/health` (public)                       | 15 minutes | 100  |
| `POST /api/v1/admin/login`               | 15 minutes | 10   |

## 📐 Conventions

- `sessionId` is a UUIDv4 generated by the server. The friendly label is `name`.
- `to` must be a valid WhatsApp ID: `^[0-9]+@s\.whatsapp.net$` (e.g. `628123456789@s.whatsapp.net`).
- Message sends are **queued async**. Response is `{ status: "queued", jobId }`, not an immediate `messageId`.
- Ownership: an API key can only see and manage sessions it created. Admin (cookie or Bearer) can manage **all** sessions and templates.

## 👤 User Endpoints (API Key)

### Sessions

#### Start a New Session

- **Endpoint:** `POST /sessions/start`
- **Body:**
    ```json
    {
        "name": "billing-prod",
        "webhookUrl": "https://your-server.com/webhook"
    }
    ```

    - `name` (string, required or `sessionId` legacy): friendly session name
    - `webhookUrl` (string, optional): HTTPS URL for real-time events
- **Response:**
    ```json
    {
        "status": "pending",
        "message": "Session initiation started",
        "sessionId": "a1b2c3d4-e5f6-..."
    }
    ```
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/sessions/start \
         -H "x-api-key: wak_abc123.xxx" \
         -H "Content-Type: application/json" \
         -d '{"name": "billing-prod", "webhookUrl": "https://hooks.example.com/wa"}'
    ```

#### List Sessions

- **Endpoint:** `GET /sessions`
- **Response:**
    ```json
    {
        "sessions": [
            {
                "id": "a1b2c3d4-...",
                "name": "billing-prod",
                "status": "CONNECTED"
            }
        ]
    }
    ```
- **cURL:**
    ```bash
    curl -H "x-api-key: wak_abc123.xxx" http://localhost:3000/api/v1/sessions
    ```

#### Get Session Status

- **Endpoint:** `GET /sessions/{sessionId}/status`
- **Response:**
    ```json
    {
        "sessionId": "a1b2c3d4-...",
        "status": "CONNECTED",
        "whatsappId": "628123456789@s.whatsapp.net"
    }
    ```
- **cURL:**
    ```bash
    curl -H "x-api-key: wak_abc123.xxx" \
         http://localhost:3000/api/v1/sessions/a1b2c3d4-.../status
    ```

#### Get Session QR

Available when status is `SCANNING_QR`. Returns a base64 PNG in `qrImage`.

- **Endpoint:** `GET /sessions/{sessionId}/qr`
- **Response:**
    ```json
    {
        "sessionId": "a1b2c3d4-...",
        "status": "SCANNING_QR",
        "qrImage": "data:image/png;base64,..."
    }
    ```
- **cURL:**
    ```bash
    curl -H "x-api-key: wak_abc123.xxx" \
         http://localhost:3000/api/v1/sessions/a1b2c3d4-.../qr
    ```

#### Stop Session (Pause)

Disconnects but keeps auth data for easy reconnect.

- **Endpoint:** `POST /sessions/{sessionId}/stop`
- **Response:** `{ "status": "success", "message": "Session stopped" }`
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/sessions/a1b2c3d4-.../stop \
         -H "x-api-key: wak_abc123.xxx"
    ```

#### Logout Session (Hard Delete)

Fully removes session and auth files. Requires QR rescan to reconnect.

- **Endpoint:** `POST /sessions/{sessionId}/logout`
- **Response:** `{ "status": "success", "message": "Session logged out and data cleared" }`
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/sessions/a1b2c3d4-.../logout \
         -H "x-api-key: wak_abc123.xxx"
    ```

#### Get Session Message Log

- **Endpoint:** `GET /sessions/{sessionId}/messages/log`
- **Response:** `{ "status": "success", "messages": [...] }`
- **cURL:**
    ```bash
    curl -H "x-api-key: wak_abc123.xxx" \
         http://localhost:3000/api/v1/sessions/a1b2c3d4-.../messages/log
    ```

### Messaging

All messaging endpoints require the session to be `CONNECTED`.

#### Send Text

- **Endpoint:** `POST /sessions/{sessionId}/message/send/text`
- **Body:**
    ```json
    {
        "to": "628123456789@s.whatsapp.net",
        "message": "Hello!"
    }
    ```

    - `message` max 4096 characters.
- **Response:** `{ "status": "queued", "jobId": "123" }`
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/sessions/a1b2c3d4-.../message/send/text \
         -H "x-api-key: wak_abc123.xxx" \
         -H "Content-Type: application/json" \
         -d '{"to": "628123456789@s.whatsapp.net", "message": "Hello from API!"}'
    ```

#### Send Media

- **Endpoint:** `POST /sessions/{sessionId}/message/send/media`
- **Body:**
    ```json
    {
        "to": "628123456789@s.whatsapp.net",
        "type": "image",
        "mediaUrl": "https://example.com/image.png",
        "caption": "Check this out"
    }
    ```

    - `type`: `image`, `video`, or `document`
    - `caption` max 1024 characters
    - `mediaUrl` must be a valid HTTP(S) URI
- **Response:** `{ "status": "queued", "jobId": "123" }`
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/sessions/a1b2c3d4-.../message/send/media \
         -H "x-api-key: wak_abc123.xxx" \
         -H "Content-Type: application/json" \
         -d '{"to": "628123456789@s.whatsapp.net", "type": "image", "mediaUrl": "https://example.com/image.png", "caption": "Hello"}'
    ```

#### Send File (Multipart)

Upload files directly via `multipart/form-data`. Max 10 files. Backend validates file magic bytes for security.

- **Endpoint:** `POST /sessions/{sessionId}/message/send/file`
- **Form fields:**
    - `to` (required)
    - `files` (one or more file binaries)
    - `captions` (optional, array of strings, one per file)
- **Response:**
    ```json
    {
        "status": "success",
        "jobs": [{ "file": "image1.png", "status": "queued", "jobId": "123" }]
    }
    ```
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/sessions/a1b2c3d4-.../message/send/file \
         -H "x-api-key: wak_abc123.xxx" \
         -F "to=628123456789@s.whatsapp.net" \
         -F "files=@/path/to/image1.png" \
         -F "captions=Hello" \
         -F "files=@/path/to/doc.pdf" \
         -F "captions=Report"
    ```

#### Send Template

- **Endpoint:** `POST /sessions/{sessionId}/message/send/template`
- **Body:**
    ```json
    {
        "to": "628123456789@s.whatsapp.net",
        "templateName": "welcome_message",
        "variables": { "name": "John" }
    }
    ```
- **Response:** `{ "status": "queued", "jobId": "123" }`
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/sessions/a1b2c3d4-.../message/send/template \
         -H "x-api-key: wak_abc123.xxx" \
         -H "Content-Type: application/json" \
         -d '{"to": "628123456789@s.whatsapp.net", "templateName": "welcome_message", "variables": {"name": "John"}}'
    ```

### Templates

#### Create Template

- **Endpoint:** `POST /templates`
- **Body:**
    ```json
    {
        "name": "welcome_message",
        "content": "Hello {{name}}, welcome!",
        "language": "en",
        "category": "marketing"
    }
    ```

    - `name`: 3-64 chars, `[a-zA-Z0-9_-]` only
    - `content`: max 4096 chars
    - `language`: 2-letter ISO code, default `en`
- **Response:** `{ "status": "success", "template": { ... } }`
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/templates \
         -H "x-api-key: wak_abc123.xxx" \
         -H "Content-Type: application/json" \
         -d '{"name": "welcome_message", "content": "Hello {{name}}", "language": "en"}'
    ```

#### List Templates

- **Endpoint:** `GET /templates`
- **Response:** `{ "status": "success", "templates": [...] }`
- **cURL:**
    ```bash
    curl -H "x-api-key: wak_abc123.xxx" http://localhost:3000/api/v1/templates
    ```

#### Get Template

- **Endpoint:** `GET /templates/{name}`
- **Response:** `{ "status": "success", "template": { ... } }`

#### Update Template

- **Endpoint:** `PUT /templates/{name}`
- **Body:** `{ "content": "Updated", "language": "id" }`
- **Response:** `{ "status": "success", "template": { ... } }`

#### Delete Template

- **Endpoint:** `DELETE /templates/{name}`
- **Response:** `{ "status": "success", "message": "Template deleted" }`

## 🛡️ Admin Endpoints

Admin endpoints accept **either** the admin cookie (from UI login) **or** an admin Bearer token.

### Admin Authentication

#### Login (UI)

- **Endpoint:** `POST /api/v1/admin/login`
- **Body:** `{ "username": "admin", "password": "..." }`
- **Response:** `{ "status": "success", "message": "Login successful" }` (sets `admin_token` cookie)
- **cURL:**
    ```bash
    curl -X POST http://localhost:3000/api/v1/admin/login \
         -H "Content-Type: application/json" \
         -d '{"username": "admin", "password": "yourpassword"}' \
         -c cookies.txt
    ```

#### Logout

- **Endpoint:** `POST /api/v1/admin/logout`
- **Response:** `{ "status": "success", "message": "Logged out" }`

#### Me

- **Endpoint:** `GET /api/v1/admin/me`
- **Response:** `{ "status": "success", "admin": { "username": "admin" } }`

### Admin Tokens (Programmatic Admin Access)

Admin tokens are used for server-to-server access via `Authorization: Bearer <token>`.

#### List Admin Tokens

- **Endpoint:** `GET /api/v1/admin/tokens`
- **Response:**
    ```json
    {
        "status": "success",
        "adminTokens": [
            {
                "id": "...",
                "name": "platform-billing",
                "prefix": "wak_adm_abc123",
                "created_at": "...",
                "last_used_at": "...",
                "revoked_at": null,
                "expires_at": null,
                "created_by": "admin"
            }
        ]
    }
    ```

#### Create Admin Token

- **Endpoint:** `POST /api/v1/admin/tokens`
- **Body:** `{ "name": "platform-billing", "expiresAt": "2026-12-31T23:59:59Z" }`
    - `expiresAt` is optional.
- **Response:**
    ```json
    {
        "status": "success",
        "adminToken": {
            "id": "...",
            "name": "platform-billing",
            "prefix": "wak_adm_abc123",
            "token": "wak_adm_abc123.xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
        }
    }
    ```
    > The full `token` is shown **only once** at creation. Store it securely.

#### Regenerate Admin Token

- **Endpoint:** `POST /api/v1/admin/tokens/{id}/regenerate`
- **Response:** same shape as create (new `token` shown once)

#### Revoke Admin Token

- **Endpoint:** `POST /api/v1/admin/tokens/{id}/revoke`
- **Response:** `{ "status": "success", "message": "Admin token revoked" }`
- **Note:** You cannot revoke the token currently used for the request.

#### Delete Admin Token

- **Endpoint:** `DELETE /api/v1/admin/tokens/{id}`
- **Response:** `{ "status": "success", "message": "Admin token deleted" }`
- **Note:** You cannot delete the token currently used for the request.

## 🔧 Operational Endpoints

### Health

- **Liveness:** `GET /health/live`
    - Response: `{ "status": "ok", "uptime": 123 }`
- **Readiness:** `GET /health/ready`
    - Unauthenticated: checks DB and Redis.
    - Authenticated (cookie or API key): includes `system` (uptime, memory) and `sessions` (active/total counts).
    - Returns `503` if a dependency is down.

### Metrics (Prometheus)

- **Endpoint:** `GET /metrics`
- **Auth:** `Authorization: Bearer <METRICS_TOKEN>` (unless `METRICS_PUBLIC=true`)
- **Response:** Prometheus exposition format

### API Docs (Swagger UI)

- **Endpoint:** `GET /docs`
- **Auth:** admin cookie or `DOCS_PUBLIC=true`
- Serves interactive OpenAPI documentation.

## 🪝 Webhooks

Set a `webhookUrl` when starting a session. The gateway will `POST` to that URL with event payloads.

### Webhook Security

- HTTPS is enforced unless `WEBHOOK_ALLOW_HTTP=true`.
- Private IPs are blocked (SSRF protection).
- If `WEBHOOK_SIGNING_SECRET` is set, the request includes:
    - `X-Webhook-Signature: sha256=<hmac>`
- Headers sent:
    - `Content-Type: application/json`
    - `User-Agent: WhatsApp-Gateway/1.0`
    - `X-Request-ID: <request-id>` (if available)

### Event Types

#### `qr_code`

Sent when a new QR code is available for scanning.

```json
{
    "event": "qr_code",
    "sessionId": "a1b2c3d4-...",
    "qrCode": "2@...base64_or_string...",
    "timestamp": 1715683200000
}
```

#### `connection_update`

Sent on connection state changes.

```json
{
    "event": "connection_update",
    "sessionId": "a1b2c3d4-...",
    "status": "CONNECTED",
    "timestamp": 1715683200000
}
```

Status values: `CONNECTED`, `DISCONNECTED`, `SCANNING_QR`.

#### `message_received`

Sent when an incoming message is received.

```json
{
    "event": "message_received",
    "sessionId": "a1b2c3d4-...",
    "message": {
        "key": { "remoteJid": "628123456789@s.whatsapp.net", "id": "..." },
        "message": { "conversation": "Hello there!" }
    },
    "timestamp": 1715683200000
}
```

#### `message_status_update`

Sent when a message delivery status changes (e.g., read, delivered).

```json
{
    "event": "message_status_update",
    "sessionId": "a1b2c3d4-...",
    "messageId": "...",
    "status": "read",
    "timestamp": 1715683200000
}
```

## ❌ Error Reference

| HTTP | Code                               | Meaning                                  |
| ---- | ---------------------------------- | ---------------------------------------- |
| 400  | `VALIDATION_ERROR`                 | Request body or params failed validation |
| 401  | `AUTH_FAILED` / `UNAUTHORIZED`     | Missing or invalid credentials           |
| 403  | —                                  | Forbidden (e.g., invalid JWT role)       |
| 404  | `NOT_FOUND` / `SESSION_NOT_ACTIVE` | Resource/session not found or not active |
| 409  | —                                  | Conflict (rare)                          |
| 429  | —                                  | Rate limit exceeded                      |
| 500  | `CONFIG_ERROR`                     | Server misconfiguration                  |

Error response shape:

```json
{
    "status": "error",
    "message": "Human readable description",
    "code": "VALIDATION_ERROR"
}
```

## 🔄 End-to-End Examples

### 1. User: Create Session and Send a Message

```bash
# 1. Start session
SESSION=$(curl -s -X POST http://localhost:3000/api/v1/sessions/start \
  -H "x-api-key: wak_abc123.xxx" \
  -H "Content-Type: application/json" \
  -d '{"name": "my-session", "webhookUrl": "https://hooks.example.com/wa"}' | jq -r '.sessionId')

# 2. Poll QR until connected (or scan from webhook)
curl -s -H "x-api-key: wak_abc123.xxx" \
  "http://localhost:3000/api/v1/sessions/${SESSION}/qr"

# 3. Send text
curl -X POST "http://localhost:3000/api/v1/sessions/${SESSION}/message/send/text" \
  -H "x-api-key: wak_abc123.xxx" \
  -H "Content-Type: application/json" \
  -d '{"to": "628123456789@s.whatsapp.net", "message": "Hello!"}'
```

### 2. Admin (UI Cookie): Manage a User's API Key and Session

```bash
# 1. Login and save cookie
curl -X POST http://localhost:3000/api/v1/admin/login \
  -H "Content-Type: application/json" \
  -d '{"username": "admin", "password": "secret"}' \
  -c cookies.txt

# 2. Create an API key for a user
curl -X POST http://localhost:3000/api/v1/admin/api-keys \
  -b cookies.txt \
  -H "Content-Type: application/json" \
  -d '{"name": "customer-a-key"}'

# 3. List all sessions (admin sees everything)
curl -H "x-api-key: admin-bearer-or-cookie" \
  http://localhost:3000/api/v1/sessions

# 4. Stop any session
curl -X POST http://localhost:3000/api/v1/sessions/a1b2c3d4-.../stop \
  -b cookies.txt
```

### 3. Admin (Programmatic Bearer): Provision and Cleanup from Another Platform

```bash
# 1. Create an admin token once from the UI, then store it securely.
ADMIN_TOKEN="wak_adm_xxxxxxxx.yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy"

# 2. Create a user API key
curl -X POST http://localhost:3000/api/v1/admin/api-keys \
  -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"name": "auto-generated-ci"}'

# 3. Start a session on behalf of that API key
curl -X POST http://localhost:3000/api/v1/sessions/start \
  -H "Authorization: Bearer ${ADMIN_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{"name": "ci-session", "apiKeyId": "<user-api-key-id>"}'

# 4. Revoke a compromised key
curl -X POST http://localhost:3000/api/v1/admin/api-keys/<id>/revoke \
  -H "Authorization: Bearer ${ADMIN_TOKEN}"
```
